## Игровые механики (реализованы)
- Поле 10x20, 7-bag рандомизатор, SRS-поворот с полными кик-оффсетами (в т.ч. для I)
- Hold, очередь из 5 фигур, ghost-подсказка
- Lock delay 500 мс (до 15 сбросов), гравитация по уровню, soft/hard drop
- Очки: одиночные/двойные/тройные/тетрис, T-spin, back-to-back, комбо, уровень
- Управление: стрелки, Z/X поворот, Space, C hold, P пауза, R рестарт; тач-кнопки и свайпы

## Деплой
Статика без сборки -> Vercel отдаёт корень как есть (`vercel.json` без build-команды).
Ссылка будет вида `https://<project>-<hash>.vercel.app`.

# Задача: PDF-описание проекта (портфолио)

**Статус:** план на согласовании с пользователем.

## Цель
Подготовить PDF-документ на русском языке (4–6 страниц A4), описывающий Neon Tetris как портфолио-проект: назначение, возможности и механики, технический стек, архитектура, тестирование, локальный запуск и деплой. Со скриншотами игры.

## Критерии готовности
- PDF лежит в `docs/Neon-Tetris-Project-Description.pdf`, открывается, объём 4–6 страниц A4.
- Текст на русском, факты соответствуют коду и README.
- 2–3 качественных скриншота: стартовый экран и геймплей (опционально — мобильный вид).
- Оформление в неоновой айдентике игры; текст читаем, ничего не обрезано, страницы не «пляшут».
- Исходники (HTML + скриншоты) лежат в `docs/`, чтобы PDF можно было пересобрать одной командой.

## Шаги
1. **Собрать факты.** Прочитать `README.md`, `PLAN.md`, `package.json`, `vercel.json`, структуру `src/`, `tests/`, `tools/`; сверить с отчётом сабагента `explore`.
2. **Подготовить скриншоты.**
   - Запустить `npm run dev` (http://localhost:3000).
   - Открыть игру в браузере (скилл `browser`), снять: стартовый экран, геймплей (Enter + несколько ходов), при желании мобильный вид (эмуляция 390×844).
   - Сохранить PNG в `docs/screenshots/`.
3. **Свёрстать `docs/project-description.html`.**
   - A4 print CSS, тёмная неоновая тема, системные шрифты (без внешних CDN).
   - Разделы: титульный блок, обзор проекта, возможности и механики, технологический стек, архитектура (схема модулей), тестирование, запуск и деплой, итог.
   - `@page`, `page-break`, `print-color-adjust: exact`; изображения — относительными путями.
4. **Собрать PDF headless-браузером.**
   - `"C:\Program Files\Google\Chrome\Application\chrome.exe" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="<abs path>" "file:///<abs path to html>"`
   - Fallback: `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`.
5. **Проверить результат.** Открыть PDF через `read` (PDF поддерживается), проверить: 4–6 страниц, нет обрезанного текста и скриншотов, читаемость. При необходимости поправить CSS и пересобрать.
6. **Завершить.** Отметить выполнение в `PLAN.md`; доложить путь к PDF, число страниц и чем проверено.

## Файлы

## Риски и ограничения
- Headless Chrome не печатает фоны без `print-color-adjust: exact` — учесть в CSS.
- Скриншоты требуют работающего dev-сервера и свободного порта 3000.
- Внешние шрифты и CDN не используем (офлайн-совместимость).
- PDF держать в разумном размере (до ~10 МБ); PNG при необходимости сжать.
